# 리디브(redev) — 서울 재개발 구역·매물 플랫폼 MVP

재개발닷컴 / 갈타맵 / 재개발뷰의 강점을 합친 정비사업 전문 플랫폼 MVP.

## 수익 구조 (3-트랙)

| 트랙 | 요금 | 내용 |
|---|---|---|
| 🔍 구역 실거래가·사업단계 | **무료** | 유입 트래픽용. 지도 경계 폴리곤, 유형·단계 필터, 실거래 배수 분석 |
| 🏢 중개사 매물 등록 | **유료** | 단건 등록권 9만원 / 월 무제한 구좌 29만원 (모의 결제) |
| 🔓 매수자 검증 매물 열람 | **유료** | 건당 3만원 열람권 → 초기투자금·예상분담금 시뮬레이션 + 중개사 직통 연락처 |

## 주요 화면

- `/` **구역 탐색기**: Leaflet 지도에 **서울시 정비구역 전수 1,835곳** 경계 폴리곤(6분류 색상, Canvas 렌더), **수도권 지하철 노선·역명 레이어(기본 ON, 🚇 토글)**, 구역명·지번 별칭 검색, 클릭 시 상세 패널
  - 재개발닷컴 스타일: 유형(신통기획/모아타운/도공복/일반재개발)·단계 필터 칩, 등록매물수·최저가·최저 초기투자금 뱃지
  - 전수 구역 클릭 → 서울시 고시 데이터(구역명·자치구·사업유형·추진단계·고시면적 ㎡/평·경계 도형·기준일)
  - 범례에 유형별 실제 구역 수(일반재개발 681 · 가로주택 718 · 소규모 194 · 신통기획 118 · 모아타운 90 · 도공복 34)
  - **공식 구역명·지번 별칭**: `사당동 419-1`로도 `사당15구역`으로도 같은 구역이 검색된다(서울시 고시·정보몽땅으로 확인한 이름)
  - **구역계 미고시 후보지**(예: 사당21구역 — 2026-05-07 후보지 선정)는 경계를 지어내지 않고 지도에 **점**으로 표시
  - 재개발뷰 스타일: **실거주 의무 / 토허제 적용** 뱃지, **예상 입주 구간**
  - 갈타맵 스타일 상세: 사업개요(추정비례율·세대수·시공사), 추진경과 타임라인(고시/공고 링크 자리), 실거래 테이블(**대지지분·공시가 배수**·유형별 추이), 구역 내 매물 비교 컬럼(매매가·초기투자금·추정 권리가액·불하금 유무·참고순위)
- `/listings` **검증 매물**: 전체 매물 비교 + 열람권 모의 결제 → 총투자금 시뮬레이션(매매가·불하금·부대비용·초기투자금·전세 회수·추가분담금·추정 권리가액·총 소요자금)
- `/register` **중개사 매물 등록**: 요금제 선택 → 실무 필드 입력(불하금 포함 여부·감정평가액·프리미엄 자동·**초기투자금 자동 계산**) → 모의 결제 → 등록 완료

## 기술 스택

Next.js 16 (App Router, TypeScript) · Tailwind CSS 4 · Leaflet 1.9 (react-leaflet 5, OpenStreetMap 타일 — **지도 API 키 불필요**) · Supabase(Postgres) 준비

## 실행

```bash
cp .env.example .env.local   # 값 없이도 mock 데이터로 동작
npm install
npm run dev                  # http://localhost:3100
npm run build && npm start   # 프로덕션 빌드 확인
npm run geojson              # 구역 폴리곤 → public/data/zones.geojson
npm run subway               # 지하철 노선·역 → public/data/subway-*.{geojson,json}  (Overpass API)
```

## Supabase 배포

1. supabase.com에서 프로젝트 생성 → SQL Editor에 `supabase/schema.sql` 실행
   (tables: `zones`, `transactions`, `brokers`, `listings`, `unlocks`, `broker_subscriptions` + RLS 전면)
2. `.env.local`에 `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` 입력
3. Vercel: GitHub 저장소 연결 → 환경변수 동일 입력 → Deploy

## 공공 데이터 연동

- **실거래가**: 국토부 실거래가 API — `src/lib/data-provider.ts` 어댑터 골격 참고
- **구역 경계(적용됨)**: 2-소스 병합 + 공식 명칭 보강 — **서울시 정비구역 전수 1,835곳**
  1. 서울 열린데이터광장 「서울시 도시계획사업 현황(서울플랜+)」 OA-22712 (CC-Zero) — 사업유형·추진단계·고시면적,
     기본 도형. 2,776개 레코드 중 정비사업 본연(재개발·재건축·신통기획·모아타운·가로주택·자율주택·
     소규모·재정비촉진구역·도공복) 2,068개를 골라 **같은 구역의 중복 레코드를 병합**해 1,834곳으로 정리.
     도시재생활성화지역(`성수동` 886,560㎡ 같은 동 경계)이나 재정비촉진지구(상위 지구), 역세권사업은 제외.
  2. 서울 열린데이터광장 「서울시 의제처리구역 위치정보」 OA-20957 (UQ181, 2026-09) — **필지 경계를 따라가는 정밀 도형**.
     같은 구역이 있으면 굴곡량이 더 많은 도형을 채택한다(예: 성수전략2구역 10점 → 125점, 전수 중 57곳 교체).
  3. **공식 명칭·신규 후보지 보강** `scripts/data/official-supplement.json` — 반기 갱신 데이터의 두 구멍을 메운다.
     · 지번으로만 실린 구역을 공식 이름으로 (예: `사당동 419-1` → **사당15구역**, `사당동 288` → **사당12구역**)
     · 갱신 사이에 선정돼 빠진 후보지 추가 (예: **사당21구역** — 2026-05-07 선정, 113,859㎡)
     경계는 공식 도형이 확인된 것만 쓰고, 정비구역 지정 전 후보지는 **점**으로만 표시한다.
  두 SHP 모두 EPSG:5174 → WGS84 변환. 재현 절차는 `scripts/README-gis.md`,
  변환 스크립트는 `scripts/import-seoul-zones.py` (+ `apply-official-supplement.py`)
- **지하철 노선·역(적용됨)**: OpenStreetMap Overpass(ODbL) `route=subway` 관계 + 역 정차 노드 →
  `public/data/subway-lines.geojson`(20개 노선)·`subway-stations.json`(574역).
  생성 `python3 scripts/build-subway-dataset.py`, 상세 `scripts/README-subway.md`
- **정비사업 단계·비례율**: 정비사업 정보몽땅 (eum.go.kr)

  필요한 구역(성수전략2·성수전략1/3·장위8 등)에만 사용하며, 상세 패널에 「경계 도형」·「경계 명칭」으로
  출처를 표시한다. **상업 서비스 출시 전 이 데이터의 이용범위(공공누리 4유형) 확인이 필요하다.**

  지도 하단 저작자 표기에 함께 표시한다. 노선색은 서울교통공사·국가철도공단 표준색.
- **세대수·비례율·시공사·입주시기·실거래·매물**: 서비스 구조 검증용 **샘플**.

  "참고용 추정" 고지를 유지하세요.
