# 리디브(redev) — 서울 재개발 구역·매물 플랫폼 MVP

재개발닷컴 / 갈타맵 / 재개발뷰의 강점을 합친 정비사업 전문 플랫폼 MVP.

## 수익 구조 (3-트랙)

| 트랙 | 요금 | 내용 |
|---|---|---|
| 🔍 구역 실거래가·사업단계 | **무료** | 유입 트래픽용. 지도 경계 폴리곤, 유형·단계 필터, 실거래 배수 분석 |
| 🏢 중개사 매물 등록 | **유료** | 단건 등록권 9만원 / 월 무제한 구좌 29만원 (모의 결제) |
| 🔓 매수자 검증 매물 열람 | **유료** | 건당 3만원 열람권 → 초기투자금·예상분담금 시뮬레이션 + 중개사 직통 연락처 |

## 주요 화면

- `/` **구역 탐색기**: **카카오맵(JS SDK)** 위에 **서울시 정비구역·역세권·장기전세 전수 2,179곳** 경계 폴리곤(8분류 색상, 단일 Canvas 오버레이), 구역명·지번 별칭 검색, 클릭 시 상세 패널
  - **주소 검색 → 소속 정비구역 자동 판별**: 검색창에 `신림동 362-32`·`테헤란로 152`처럼 지번·도로명을 치면
    카카오 `Geocoder.addressSearch`(결과 없으면 `Places.keywordSearch`, `서울 ` 보정)로 서울 주소 후보를 함께 보여주고,
    고르면(엔터면 첫 후보) **전체 2,179구역 폴리곤에 광선교차(Point-in-Polygon)** 판정을 한다 —
    Polygon·MultiPolygon·구멍(hole) 처리 포함. 주소 위치에 핀+말풍선을 찍고
    **진행 중 구역이면 `✅ ○○구역 포함` + 그 구역 선택·상세 패널**, 겹친 구역이 있으면 겹침 목록도 보여준다.
    **준공 구역**이면 `🏁 준공 완료된 ○○구역 내 주소`로 알리고 준공 토글을 자동으로 켜며,
    **경계 미고시 후보지**(사당21구역 등 점 표시) 250m 안이면 `⚠️ … 인근 주소`로 안내한다.
    **구역 밖**이면 `정비구역 밖 주소입니다` + 가장 가까운 구역 1~3곳(직선거리 m/km, 클릭 시 이동).
    핀은 `핀 지우기 ✕`로 지운다. 검증: `scripts/verify-address-search.py`
  - **지도가 화면 전체** (재개발뷰·네이버지도 방식): 헤더 52px만 남기고 지도가 뷰포트를 채운다. 검색·필터·범례는 지도 위에 떠 있는 카드(접기 가능), 구역 상세는 데스크톱 오른쪽 드로어 / 모바일 아래 시트
  - **휠 줌·드래그 중에도 경계가 지도에 정확히 붙어 있다 (프레임 지연 0)**: 배율을 추정하지 않는다.
    카카오는 자기 벡터 레이어(SVG)의 `left/top/width/height` 를 **매 프레임 JS 로** 바꾸므로,
    같은 레이어에 아주 작은 투명 사각형 두 개(기준점)를 그려 두고 그 **실제 화면 좌표**에서 지도
    변환(배율·기준점)을 그대로 읽는다. 카카오가 그 레이어를 갱신하는 그 순간을 `MutationObserver`
    로 잡아 같은 프레임의 페인트 전에 다시 그리므로, 줌 중심이 커서여도·관성 드래그여도 경계가
    지도에서 떨어지지 않는다. 검증: `scripts/verify-zoom-sync.py` (휠·버튼·커서 치우친 줌·드래그·
    플릭·스카이뷰·깊은 확대·넓은 축소 전 시나리오에서 **2px 이내 100%**, 최대 오차 1.2px)
  - 카카오 기본지도라 **지하철 출구번호·역명·건물명·지번**이 그대로 나온다 (별도 지하철 레이어 불필요)
  - 지도 위 토글: **스카이뷰**(위성+라벨 HYBRID) · **지적편집도**(USE_DISTRICT) · **준공 포함(357곳, 기본 OFF)** · 확대/축소
  - 카카오 키·도메인이 준비되지 않으면 **자동으로 Leaflet/OSM 지도로 폴백**(지도가 비지 않게, 지도 위에 작은 안내)
  - 재개발닷컴 스타일: 유형(일반재개발/신통기획/모아타운/도공복/가로주택/소규모/**역세권/장기전세**)·단계 필터 칩, 등록매물수·최저가·최저 초기투자금 뱃지
    · 유형 칩은 서울시 전수 레이어에도 걸린다 — 고른 유형만 지도·범례에 남고, 검색과 주소 판정은 필터와 무관하게 전체를 본다
  - 전수 구역 클릭 → 서울시 고시 데이터(구역명·자치구·사업유형·추진단계·고시면적 ㎡/평·경계 도형·기준일)
  - 범례에 유형별 실제 구역 수(일반재개발 674 · 가로주택 718 · 역세권 196 · 소규모 194 · 장기전세 159 · 신통기획 110 · 모아타운 94 · 도공복 34)
    · **역세권** = 역세권활성화·청년안심주택(주황), **장기전세** = 장기전세주택·미리내집(마젠타) — 상세 패널의 ‘사업유형’에 소분류가 그대로 나온다
  - **공식 구역명·지번 별칭**: `사당동 419-1`로도 `사당15구역`으로도 같은 구역이 검색된다(서울시 고시·정보몽땅으로 확인한 이름)
  - **구역계 미고시 후보지**(예: 사당21구역 — 2026-05-07 후보지 선정)는 경계를 지어내지 않고 지도에 **점**으로 표시
  - 재개발뷰 스타일: **실거주 의무 / 토허제 적용** 뱃지, **예상 입주 구간**
  - 갈타맵 스타일 상세: 사업개요(추정비례율·세대수·시공사), 추진경과 타임라인(고시/공고 링크 자리), 실거래 테이블(**대지지분·공시가 배수**·유형별 추이), 구역 내 매물 비교 컬럼(매매가·초기투자금·추정 권리가액·불하금 유무·참고순위)
- `/listings` **검증 매물**: 전체 매물 비교 + 열람권 모의 결제 → 총투자금 시뮬레이션(매매가·불하금·부대비용·초기투자금·전세 회수·추가분담금·추정 권리가액·총 소요자금)
- `/register` **중개사 매물 등록**: 요금제 선택 → 실무 필드 입력(불하금 포함 여부·감정평가액·프리미엄 자동·**초기투자금 자동 계산**) → 모의 결제 → 등록 완료

## 기술 스택

Next.js 16 (App Router, TypeScript) · Tailwind CSS 4 · **카카오맵 JavaScript SDK**(기본 지도) + Leaflet 1.9/OpenStreetMap(폴백) · Supabase(Postgres) 준비

> **지도 설정**: `.env.local` 의 `NEXT_PUBLIC_KAKAO_MAP_APP_KEY` 에 카카오 **JavaScript 키**를 넣고,
> 카카오 Developers → 플랫폼 → Web 사이트 도메인에 배포 주소(`https://redev-platform-iota.vercel.app`)와
> 로컬 주소(`http://localhost:3100`, `http://localhost:3000`)를 등록한다.
> 키가 없거나 SDK가 뜨지 않으면 자동으로 OSM 지도로 폴백한다(Admin 키·REST 키는 넣지 말 것 — 서버 전용 비밀 키).

## 실행

```bash
cp .env.example .env.local   # 값 없이도 mock 데이터로 동작
npm install
npm run dev                  # http://localhost:3100
npm run build && npm start   # 프로덕션 빌드 확인
npm run geojson              # 구역 폴리곤 → public/data/zones.geojson
npm run subway               # 지하철 노선·역 → public/data/subway-*.{geojson,json}  (Overpass API)
```

## Supabase 배포

1. supabase.com에서 프로젝트 생성 → SQL Editor에 `supabase/schema.sql` 실행
   (tables: `zones`, `transactions`, `brokers`, `listings`, `unlocks`, `broker_subscriptions` + RLS 전면)
2. `.env.local`에 `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` 입력
3. Vercel: GitHub 저장소 연결 → 환경변수 동일 입력 → Deploy

## 공공 데이터 연동

- **실거래가**: 국토부 실거래가 API — `src/lib/data-provider.ts` 어댑터 골격 참고
- **구역 경계(적용됨)**: 2-소스 병합 + 공식 명칭 보강 — **서울시 정비구역·역세권·장기전세 전수 2,179곳**
  1. 서울 열린데이터광장 「서울시 도시계획사업 현황(서울플랜+)」 OA-22712 (CC-Zero) — 사업유형·추진단계·고시면적,
     기본 도형. 2,776개 레코드 중 정비사업 본연(재개발·재건축·신통기획·모아타운·가로주택·자율주택·
     소규모·재정비촉진구역·도공복) 2,068개 + 역세권·장기전세 사업(역세권활성화·청년안심주택·
     장기전세주택·미리내집) 411개를 골라 **같은 구역의 중복 레코드를 병합**해 2,179곳으로 정리.
     도시재생활성화지역(`성수동` 886,560㎡ 같은 동 경계)이나 재정비촉진지구(상위 지구)는 제외.
  2. 서울 열린데이터광장 「서울시 의제처리구역 위치정보」 OA-20957 (UQ181, 2026-09) — **필지 경계를 따라가는 정밀 도형**.
     같은 구역이 있으면 굴곡량이 더 많은 도형을 채택한다(예: 성수전략2구역 10점 → 125점, 전수 중 63곳 교체).
  3. **공식 명칭·신규 후보지 보강** `scripts/data/official-supplement.json` — 반기 갱신 데이터의 두 구멍을 메운다.
     · 지번으로만 실린 구역을 공식 이름으로 (예: `사당동 419-1` → **사당15구역**, `사당동 288` → **사당12구역**)
     · 갱신 사이에 선정돼 빠진 후보지 추가 (예: **사당21구역** — 2026-05-07 선정, 113,859㎡)
     경계는 공식 도형이 확인된 것만 쓰고, 정비구역 지정 전 후보지는 **점**으로만 표시한다.
  두 SHP 모두 EPSG:5174 → WGS84 변환. 재현 절차는 `scripts/README-gis.md`,
  변환 스크립트는 `scripts/import-seoul-zones.py` (+ `apply-official-supplement.py`)
- **지하철 노선·역(적용됨)**: OpenStreetMap Overpass(ODbL) `route=subway` 관계 + 역 정차 노드 →
  `public/data/subway-lines.geojson`(20개 노선)·`subway-stations.json`(574역).
  생성 `python3 scripts/build-subway-dataset.py`, 상세 `scripts/README-subway.md`
- **정비사업 단계·비례율**: 정비사업 정보몽땅 (eum.go.kr)

## 소스 데이터 고지

  기준 2026-09, **CC-Zero 상업적 이용 가능**) **실데이터**. 좌표계 EPSG:5174(Korean 1985, Bessel)를

- **정밀 경계 도형**: 서울 열린데이터광장 「서울시 의제처리구역 위치정보」 (OA-20957, 기준 2026-09,
  **공공누리 4유형 — 출처표시·상업적 이용금지·변경금지**) 실데이터. 필지 경계를 따라가는 도형이
  필요한 구역(성수전략2·성수전략1/3·장위8 등)에만 사용하며, 상세 패널에 「경계 도형」·「경계 명칭」으로
  출처를 표시한다. **상업 서비스 출시 전 이 데이터의 이용범위(공공누리 4유형) 확인이 필요하다.**
- **지하철 노선 형상·역 좌표·역명**: © OpenStreetMap contributors (**ODbL 1.0**).
  지도 하단 저작자 표기에 함께 표시한다. 노선색은 서울교통공사·국가철도공단 표준색.
- **세대수·비례율·시공사·입주시기·실거래·매물**: 서비스 구조 검증용 **샘플**.
  실운영 전 국토부 실거래가 API·정보몽땅으로 교체하고, 추정치(비례율·분담금·권리가액)에는
  "참고용 추정" 고지를 유지하세요.
